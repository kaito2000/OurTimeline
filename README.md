# OurTimeline（ふたりのクロニクル）

出会いから現在、そして未来の約束までを1本の縦軸タイムラインで紡ぎ、Supabaseを活用して夫婦2端末間で完全リアルタイム同期するPWA（Progressive Web App）です。

---

## 🌟 主な機能と特徴

1. **1本の美しい縦軸タイムライン**:
   - 降順整列（未来 ➔ TODAYマーカー ➔ 過去）。
   - 年ごとのセパレーター（2025年、2024年...）を自動グループ化。
   - 交際記念日・結婚記念日からの経過日数（「Day ○○」）を上部に常時表示。
2. **過去と未来のビジュアル切り替え**:
   - **過去の思い出**: 実線ボーダー、ソリッドカード、写真表示、拡大モーダル。
   - **未来の約束・目標**: 点線ボーダー、半透明カード、「未来の約束」バッジ。期日超過後や達成時はワンタップで「達成（過去イベント化）」可能。
3. **クライアント側自動WebP圧縮**:
   - HTML5 Canvasを用いて、長辺最大1200pxに自動リサイズ。
   - `image/webp`（品質0.8）に自動変換してからアップロード（ファイルサイズを70〜90%削減し、Supabaseの無料枠1GBを保護）。
4. **0秒ペアリング & 銀行水準のセキュリティ**:
   - メールアドレスやパスワード認証は一切不要。
   - 発行された共有URL（`?pair=UUID&key=SECRET`）をパートナーがブラウザで開くだけで即座に同期完了。
   - 暗号学的な256bit秘密鍵とSupabase Row Level Security (RLS) により、**URLを知らない第三者は他人の思い出を1件も閲覧・改ざん・削除できません**。
5. **完全リアルタイム同期 & オフライン対応**:
   - Supabase Realtime APIにより、片方が投稿した思い出が相手の画面にリロードなしで即座に反映。
   - Service WorkerとLocalStorageにより、地下鉄や電波の届かないオフライン環境でも年表を即座に開いて閲覧・操作可能。

## 🚀 セットアップ手順

### 1. Supabaseプロジェクトの準備

1. [Supabase](https://supabase.com/) で新規プロジェクトを作成します。
2. ダッシュボードの **SQL Editor** を開き、[`supabase/schema.sql`](./supabase/schema.sql) の内容を貼り付けて実行（Run）します。
   - `pairs` テーブル、`timeline_events` テーブルが作成されます。
   - 時系列インデックス、Realtime、RLSセキュリティポリシー、Storageバケット `trip-photos` が自動構成されます。
3. **Project Settings > API** から以下を取得します:
   - `Project URL`
   - `Project API Keys` (anon / public)

### 2. アプリの起動と初期設定

本アプリはPure HTML/CSS/JavaScript（ES Modules）で構築されているため、任意の静的ファイルサーバーで起動できます。

```bash
# 簡易HTTPサーバーで起動する例 (Node.js)
npx serve .
# または Python
python -m http.server 8080
```

1. ブラウザでアプリを開きます（PWAのため、スマホの「ホーム画面に追加」を行うと全画面ネイティブアプリとして起動します）。
2. 右上の **⚙️ 設定** をタップし、取得した Supabase の `Project URL` と `Anon Key`、およびおふたりの「交際記念日」を入力して保存します。
3. ヘッダーの **💌 招待・共有** ボタンをタップし、発行されたURLをパートナーに送ります。
4. パートナーがURLを開くとペアリング完了！ふたりのリアルタイムタイムラインが始まります。

※SupabaseのURL・Keyが未入力の状態でも、ブラウザのローカル保存機能（モックモード）で全機能をお試しいただけます。

## 🔒 セキュリティアーキテクチャ

本アプリは、手軽なURL共有と高度なデータ保護を両立しています：

- **ペア秘密鍵（Pair Secret Key）**: Web Crypto APIによって256bitの暗号乱数を生成。
- **SHA-256ハッシュ検証**: DBには平文ではなくハッシュ値を保存。
- **PostgreSQL RLS**: クライアントからの全リクエストに含まれる `x-pair-key` カスタムヘッダーをPostgreSQL関数で検証し、正当なペア以外のアクセスをDB層で100%遮断。
- **URLサニタイズ**: 招待URLを開いた直後、`history.replaceState` によりアドレスバーからキーを除去し、ショルダーハックや履歴からの情報流出を防止。
